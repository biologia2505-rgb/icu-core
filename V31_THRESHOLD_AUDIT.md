# V31_THRESHOLD_AUDIT

Дата аудита: 12.10.2026. Статус приложения: **v31.0-dev**. Аудит касается только четырёх чисел в новом synthesis; изменения приложения не выполнялись.

**Результат: все четыре порога НЕУТВЕРЖДЁННЫЕ.** Это implementation heuristics, введённые автором реализации v31. В доступном утверждённом ТЗ нет чисел 28 и ±5 для этих величин; исходный медицинский источник для выбора этих чисел в материалах реализации не указан. Утверждение конкретных результатов кейсов A–H не является утверждением универсальных границ.

## 2. Что проверено для происхождения

- Сравнение `frozen-v30.1` (`4fcc139`) и `v31.0-dev` (`a8d7a70cd57540446c7de07b268e53b0edc69e99`): все четыре условия добавлены новым helper/synthesis; в frozen этих условий нет. Сами прежние формулы SBE_Cl/SBE_Alb существуют и сохранены.
- Прямое ТЗ пользователя для v31, особенно пп. 3–4 и A–H: утверждены формула corrected HCO₃, необходимость corroboration, осторожность Δ/Δ 1.5–2.0 и конкретные результаты случаев. **Пороги 28/±5 не утверждены.** Слова «высокий» и «выраженный» были самостоятельно превращены реализацией в эти числа.
- Проверены сохранённые `reference/ICU_CORE_validation_fixes_detailed.md`, `ICU_CORE_300_final_review_and_codex_spec.md`, `FINAL_CORE_SPEC_USER.md`, `FINAL_CORE_PRIMARY_AND_FIO2_AMENDMENT.md`, HAGMA/QC/компенсационные policy-документы и остальные Markdown references. Явного утверждения этих четырёх условий не найдено. Прежние границы измеренного HCO₃ >26 и SBE >2 относятся к другим величинам/правилам и не обосновывают corrected HCO₃ >28 либо SBE-разбивку ±5.
- `reference/ICU_CORE_validation_fixes_detailed.md:153` прямо говорит: «Любая новая медицинская формула/порог вне этого документа требует отдельного согласования». Текущий запрос дополнительно прямо запрещает изменения до решения пользователя.
- В ранее указанном разговоре «Оценка задумки ICU CORE» проверены доступные последние 10 turns. Они содержат обсуждение результатов и постановку настоящего аудита; явного утверждения четырёх чисел нет. Сообщения другого ассистента не считались доказательством утверждения пользователя.
- Проверены две публикации, уже указанные в changelog: [Aiding fluid prescription for the dysnatremias](https://pubmed.ncbi.nlm.nih.gov/9083234/) и [Hypertonic Saline Infusion for Hyponatremia: Limitations of the Adrogué–Madias and Other Formulas](https://pmc.ncbi.nlm.nih.gov/articles/PMC10278828/). В changelog они относятся к натриевому разделу; происхождение четырёх acid-base cutoffs ими не задокументировано. Для первого источника проверена доступная PubMed-запись/abstract, для второго — доступный текст.

Поиск новой публикации, которая могла бы постфактум оправдать выбранные числа, **не проводился**. Вывод означает отсутствие прослеживаемого основания в материалах реализации, а не доказательство отсутствия подобных чисел во всей медицинской литературе.

**Поправка к статусу прежней документации, без её редактирования:** фраза `CHANGELOG_v31.md:22` о соответствии «порогов синтеза» утверждённому ТЗ слишком широка. Название `v31-approved-...expectations.json` и прежняя формулировка «утверждённые правила» в `V31_EXPECTATION_CHANGES.md` не подтверждают отдельное утверждение чисел. Автор реализации ввёл их без отдельного согласования. Тесты проверяют эту реализацию, но не устанавливают её медицинское происхождение.

## 5. Поведение непосредственно около границ

### 5.1. Изолированная проверка ветки

Передача изменённой derived-величины в неизменённый `syndrome()/synthesizeAcidBase()` позволяет увидеть именно cutoff. Такие rows не следует интерпретировать как согласованные новые лабораторные данные пациента.

| Изменяемая величина; фиксированный контекст | Ниже | Ровно на границе | Выше |
|---|---|---|---|
| corrected HCO₃; C-like с подтверждённым HAGMA, SBE_Cl=+9, Δ/Δ неприменим, p.met=null | **27.99:** high=false; только HAGMA, алкализирующий component отсутствует | **28.00:** то же, поскольку `>` строгий | **28.01:** HAGMA+supported alkalinizing component; multipleMethods=true; «Смешанное нарушение» |
| SBE_Cl; HAGMA, Δ/Δ≈1.42, нет respiratoryRanges | **−5.01:** lowSID=true; HAGMA+NAGMA | **−5.00:** то же, `<=` включительно | **−4.99:** lowSID=false; только HAGMA; «Изолированное нарушение» |

Контекстные ограничения сохраняются: elevated interpretable AG/QC для corrected; respiratory-контекст для lowSID; альтернативные критерии могут сохранить компонент. Пересечение любой границы не изменяет отдельно подтверждённый источник анионов. Самостоятельный +5 Alb/Cl без AG/HCO₃-линии не создаёт supported alkalinizing component через `multipleMethods`.

Этот crossing меняет possible composition, а не даёт supported диагноз |

| SBE_Cl +4.99 / +5 / +5.01 | HCO₃=24, PaCO₂=40, Na=140, Alb=40, Lac=1, source=yes; Cl=99.01 / 99 / 98.99 | corrected≈28.99 / 29 / 29.01. +4.99: HAGMA+possible alkalinizing; +5 и +5.01: HAGMA+supported alkalinizing, multipleMethods=true |
| SBE_Alb +4.99 / +5 / +5.01 | pH=7.40, HCO₃=18, PaCO₂=18/(0.03×10^1.3), Na=140, Cl=101, Lac=1, source=yes; Alb≈21.998557 / 21.962482 / 21.926407 г/л | corrected≈31.50–31.52 и Δ/Δ≈2.25: AG/HCO₃-линия активна, Cl effect=+3 не проходит +5. Ниже +5: alkalinizing possible; на/выше +5: supported component. HAGMA+respiratory alkalosis сохраняются; classic alkalosis не появляется |

Точные операторы: corrected использует `>`, остальные — `<=`/`>=`. Для этих четырёх условий нет `representationEpsilon`/`compareExpectedRange`: значения непосредственно по разные стороны, даже отличающиеся лишь представлением floating-point, сравниваются напрямую. Это описание текущего кода, не предложение нового допуска. Например, corrected 28.01 отображается с округлением как 28.0, хотя флаг уже true.

## 6. Вариант без новых arbitrary cutoffs — только предложение

**Предпочтительный вариант: continuous evidence с явным разделением численного эффекта и диагностической уверенности.** Это проект решения для согласования; он не реализован и не считается новым clinical policy.

1. Сохранять corrected HCO₃, delta gap, SBE_Cl, SBE_Alb как непрерывные значения. Направление/вклад можно описывать количественно; не присваивать категории «выраженный» или supported процесс скачком на 28/±5. Не вводить вместо них другой общий cutoff, баллы или произвольные веса.
2. Уверенность composition закреплять за уже согласованными основаниями: независимо подтверждённые кислоты/анионы и QC, действующая область Δ/Δ и его утверждённые границы, существующие газовые/компенсационные модели, клинический контекст. Δ/Δ 1.5–2.0 сохраняет осторожную трактовку. Нормальный итоговый pH/HCO₃ не является veto существования процессов.
3. Для маскированных паттернов C/F выводить согласующиеся **численные** признаки и состояние подтверждения; конкретные утверждённые выводы C/F остаются целевыми требованиями. Они не дают автоматически универсальный новый порог. Если нужна автоматическая generalization «поддерживается несколькими методами», отдельно согласовать условия corroboration/контекст или клиническое подтверждение. Без такого решения нельзя обещать, что простое удаление четырёх сравнений сохранит все текущие expectations.
4. Лабораторный reference — возможный источник вместо универсального 28, но только явно заданный и применимый: reference измеренного HCO₃ нельзя молча объявить валидированным reference derived corrected HCO₃. AG laboratory limit уже существует; перенос его смысла в другие величины требует отдельного решения. Для SBE-разбивки референсы Na/Cl/Alb могут поддерживать контекст, но не являются готовыми reference-интервалами самих modeled contributions. При отсутствии соответствующего reference хранить численные эффекты/неопределённость, не подставлять новое default-число.
5. Сопоставлять линии с учётом общих входов. По **уже существующим формулам** corrected HCO₃ = Na − Cl + 0.25×(40 − Alb) − 12: HCO₃ сокращается алгебраически. Поэтому corrected и SBE_Cl используют общие Na/Cl, а corrected и SBE_Alb — общий Alb. Например, при Na=140/Alb=40 corrected=SBE_Cl+24: >28 означает SBE_Cl>4, а +5 Cl почти дублирует тот же сигнал. Согласование физиологических методов не означает два независимых измерения и не должно превращаться в произвольный evidence-score.

По каждому порогу рекомендация одна: **не считать утверждённым; вынести дальнейшее использование/замену на отдельное решение пользователя**. До этого решения текущая реализация остаётся нетронутой. Этот аудит не выполняет ни отключение confidence, ни откат v31.
